# V1 — Local Secure JSON Edition

This version preserves the original application's `data.json` persistence and localhost workflow while fixing the major security and reliability issues.

## Run

PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

python setup_passwords.py
$env:FLASK_SECRET_KEY="paste-a-long-random-secret-here"
$env:USER_PASSWORD_HASH="paste-user-hash-here"
$env:ADMIN_PASSWORD_HASH="paste-admin-hash-here"

python app.py
```

Open:

```text
http://127.0.0.1:8000
```

For a persistent login secret, keep `FLASK_SECRET_KEY` set between runs. Without it, a new local session key is generated whenever the app starts; that is safe for a localhost utility but logs out existing sessions after restart.

## Files

- `app.py` — Flask backend
- `public/index.html` — UI
- `public/app.js` — frontend logic
- `public/styles.css` — styling
- `setup_passwords.py` — creates password hashes
- `data.json` — created automatically

## Security changes

- Server-side Flask session authentication
- Password hashes instead of plaintext passwords
- CSRF token on state-changing API calls
- Admin authorization enforced on the server
- No trust in `X-User-Role`
- No inline JavaScript event handlers
- No `innerHTML` for stored/user-controlled data
- Server-side allow-list validation
- `NaN` / `Infinity` rejected
- Atomic JSON writes
- 1 MB request-size limit
- Basic login throttling
- Security headers and a CSP
- UUIDs generated by the browser for entry IDs
- CSV formula-injection mitigation on export
